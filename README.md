# emoji-extension-cdn

Self-hosted colour emoji web fonts for [Emoji Font Switch](../emoji-extension),
served free via [jsDelivr](https://www.jsdelivr.com/)'s GitHub endpoint.

The extension ships no font binaries at all. It loads one font, on demand,
from this repo — so the install stays a few hundred KB instead of ~100 MB,
and a font is only ever downloaded when someone actually picks that style.

| Style | File | Size | Colour | Coverage |
|---|---|---:|---|---:|

| Microsoft Fluent 3D | `fonts/microsoft-fluent-color-emoji.woff2` | 3.0 MB | COLR | 1395 |
| Microsoft Fluent Flat | `fonts/microsoft-fluent-flat-emoji.woff2` | 0.5 MB | COLR | 1395 |
| Microsoft Fluent High Contrast | `fonts/microsoft-fluent-high-contrast-emoji.woff2` | 0.5 MB | COLR | 1395 |
| Google Noto Color | `fonts/google-noto-color-emoji.woff2` | 2.0 MB | COLR | 1499 |
| Noto Emoji Mono | `fonts/google-noto-emoji-mono.woff2` | 1.0 MB | monochrome | 1489 |
| Google Blobmoji | `fonts/google-blobmoji.woff2` | 6.7 MB | CBDT | 1488 |
| Twemoji | `fonts/twemoji.woff2` | 0.5 MB | COLR | 1418 |
| OpenMoji Color | `fonts/openmoji-color.woff2` | 1.0 MB | COLR | 1958 |
| OpenMoji Black | `fonts/openmoji-black.woff2` | 0.6 MB | monochrome | 1958 |
| Firefox OS Emoji | `fonts/firefox-os-emoji.woff2` | 0.3 MB | COLR | 1035 |

**26.1 MB total** across 11 styles — smaller than the original 7, because Noto
now ships as a COLRv1 vector build (2.0 MB) instead of a CBDT bitmap one
(8.0 MB). `manifest.json` carries the authoritative per-font metadata (sizes,
SHA-256, upstream source, colour tables) and is regenerated by the build.

Two styles have known coverage gaps, both recorded in `fonts.json`: the Fluent
family has no flag glyphs at all, and Firefox OS Emoji predates Unicode 14 (no
🫠, no skin tones, no ZWJ families). Those fall back to the system font.

## Publishing to jsDelivr

jsDelivr serves any **public** GitHub repo automatically. There is no account,
no signup and no configuration — you push a tag and the files are live.

### 1. Create the GitHub repo

```bash
gh repo create emoji-extension-cdn --public --source . --remote origin
```

Or create it in the web UI and add the remote by hand:

```bash
git remote add origin https://github.com/<you>/emoji-extension-cdn.git
```

The repo **must be public**. jsDelivr cannot read private repos, and the
request will 404 with no useful error.

### 2. Commit the fonts

The fonts are committed on purpose — they *are* the artefact this repo
publishes. `build/` (the multi-hundred-MB upstream downloads) is gitignored
and must stay that way.

```bash
git add .
git commit -m "Emoji fonts, optimised for web delivery"
git push -u origin main
```

### 3. Tag a release

**Do this.** Do not serve from `@main` in production — see the caching table
below. jsDelivr resolves semver tags, so use a `v`-prefixed semver tag:

```bash
git tag v1.0.0
git push origin v1.0.0
```

### 4. Verify it is live

The first request for a file pulls it from GitHub and can take a few seconds;
everything after that is cache hits.

```bash
curl -I https://cdn.jsdelivr.net/gh/<you>/emoji-extension-cdn@v1.0.0/fonts/twemoji.woff2
```

You want `HTTP/2 200` and `content-type: font/woff2`. A `403` or `404` almost
always means one of: the repo is private, the tag was not pushed, the path is
wrong, or the file is over 20 MB.

Check every font at once from a clone of this repo:

```bash
python scripts/check_published.py --user <you> --tag v1.0.0
```

### 5. Point the extension at it

In `emoji-extension/src/data/definitions.json`, each entry's `path` is a full
jsDelivr URL. Update the user and tag:

```json
"path": "https://cdn.jsdelivr.net/gh/<you>/emoji-extension-cdn@v1.0.0/fonts/apple-emoji.woff2"
```

`scripts/emit_definitions.py` generates that file for you:

```bash
python scripts/emit_definitions.py --user <you> --tag v1.0.0 \
  --out ../emoji-extension/src/data/definitions.json
```

### URL forms and cache lifetimes

| URL | Cached for | Use for |
|---|---|---|
| `@v1.0.0` (exact tag) | **forever, immutable** | production |
| `@v1` / `@v1.0` (range) | 7 days | production, auto-picks latest patch |
| `@main` (branch) | 12 hours | never in a shipped extension |
| `@<commit-sha>` | forever, immutable | pinning a specific build |

> **Tags are immutable on jsDelivr.** Once a tagged file has been fetched it is
> stored permanently in their S3 — re-tagging or force-pushing the same tag
> will *not* change what users receive. If you ship a broken font, the only
> fix is to tag a new version and update the extension. Test with
> `scripts/verify.py` before you tag.

### Hard limits

jsDelivr rejects, for GitHub-served repos:

- **any single file over 20 MB**
- **any repo over 150 MB**

These are why the build optimises so aggressively. `build_all.py` fails the
build if either budget would be broken, because an oversized file does not
error at publish time — it simply 404s forever behind an immutable tag.

## Rebuilding the fonts

```bash
pip install -r requirements.txt
python scripts/build_all.py          # all fonts -> fonts/ + manifest.json
python scripts/build_all.py twemoji  # just one
python scripts/build_all.py --refresh  # re-download upstream sources
python scripts/verify.py             # render them all -> build/verify.png
```

Always look at `build/verify.png` before tagging. It renders every font in
headless Edge/Chrome across the cases that actually break: skin tones, ZWJ
families, flags, keycaps and recent Unicode additions.

### Refreshing Apple emoji to a newer macOS/iOS

`build_apple_emoji.py` resolves the newest upstream release automatically, so:

```bash
python scripts/build_apple_emoji.py --refresh
```

picks up whatever macOS/iOS version has shipped since. Then re-run `verify.py`,
commit, and tag a new version.

## How the optimisation works

Getting Apple's font from 116 MB to 10 MB — and everything under the 20 MB
cap — relies on three things, in `scripts/optimize_font.py`:

**1. Drop colour tables the browser ignores.** Several upstream fonts ship the
same artwork two or three times. Fluent carried SVG (41 MB) *and* CBDT (39 MB)
*and* COLR (5 MB); keeping only COLR took it from 87.8 MB to 3.0 MB. Chrome
renders COLR, CBDT/CBLC and sbix but has never supported OT-SVG.

**2. Keep only the largest bitmap strike.** Apple ships eight (20–96 px). The
browser scales from whichever is closest, so one 96 px strike covers every size.

**3. Re-encode bitmaps to a 256-colour palette.** This is the big win: Apple's
96 px strike drops from 38 MB to 12 MB with no visible difference, because
emoji artwork is flat shading and gradients rather than photography.

### The Apple shaping problem

Apple Color Emoji composes sequences with an AAT `morx` table instead of an
OpenType GSUB. That works on macOS and in HarfBuzz, but **not as a web font**:
Chrome and Firefox run every `@font-face` through OTS, the OpenType Sanitiser,
which drops AAT tables. The visible result is that single emoji render fine
while every sequence shatters:

```
👍🏽  -> thumbs-up + brown square
👨‍👩‍👧‍👦  -> man, woman, girl, boy
🇯🇵  -> nothing at all
1️⃣  -> nothing at all
```

`scripts/make_gsub.py` fixes this by recovering the rules empirically. HarfBuzz
*does* honour `morx` when it loads a font from disk, so the build shapes every
sequence in Unicode's `emoji-test.txt` against the source font, keeps the ones
that collapse to a single glyph, and emits them as GSUB ligature rules under
`ccmp`. The current build recovers **3233 rules**, after which the AAT tables
are dropped as dead weight.

If you ever swap the Apple source font, re-run `verify.py` and check the skin
tone, ZWJ, flags and keycap columns specifically. Those break silently.

### A note on Twemoji

The upstream `jdecked/twemoji` webfont is **OT-SVG only**, so in Chrome it
renders as flat black outlines from its `glyf` fallback — it looks like a
monochrome emoji set rather than a broken one, which is why it is easy to miss.
This repo uses [`mozilla/twemoji-colr`](https://github.com/mozilla/twemoji-colr)
instead, which is a COLR/CPAL build. The tradeoff is coverage: v0.7.0 is
Twemoji 14, so emoji added in Unicode 15+ (🩷, 🫨) fall back to the system font.
